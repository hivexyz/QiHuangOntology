# 中医本体基座改进实施审计 v0.1

## 1. 文档定位

本文档用于记录《中医本体基座改进计划 v0.1》当前已经落地的工程改进、验证证据与剩余缺口。

本文档不是新的规划文档，而是阶段性实施审计，用于回答三个问题：

1. 哪些改进已经进入代码和测试。
2. 哪些改进仍只是部分完成。
3. 后续继续优化时应优先补哪些缺口。

---

## 2. 当前总体结论

当前项目已经从“知识增强审核系统”明显推进到“中医本体基座 + 多应用投影”的形态。

已经完成或显著推进的主线包括：

- `KnowledgeCard` 投影化。
- assertion-first 查询与审核消费。
- relation schema/canonical relation 统一校验。
- publish 前 staged ontology validation gate。
- `ConditionSet` 运行时匹配。
- `Mention -> NormalizationDecision -> Concept` 导入治理前移。
- `NormalizationDecision` 的 `resolved / unresolved / ambiguous / rejected` 最小闭环。
- normalization governance queue、单条 review、批量 review。
- 人工归一结果沉淀为 draft alias，ConceptAlias 可发布或拒绝。
- 方剂君臣佐使的方剂上下文化条件。
- 性味属性分类与 `NatureFlavor` 最小独立建模。
- 五行生克乘侮关系最小图谱。
- 归经到脏腑关系最小图谱。
- 经络系统与脏腑节点一等公民化的最小闭环。
- 腧穴语境下经络到病候表现关系的最小闭环。
- 剂量范围、单位、频次的最小结构化。
- moderation `SemanticTrace` 最小链路。

但仍未完全完成的部分包括：

- 完整的术语资源批次审批流。
- 更完整的经络/脏腑体系。
- 更复杂的剂量风险推理。
- 跨应用完整 `SemanticTrace`。
- 前端治理工作台。

## 6. 剩余高优先级缺口

### 6.1 术语资源版本级发布

当前 alias 可以 draft/published/rejected，也可以按 alias_ids 发布为 `terminology_resource` version，并支持 rollback；但还没有更完整的批次审批流。

建议后续补：

- `TerminologyVersion`
- alias 变更批次
- terminology batch approval workflow

### 6.2 完整 SemanticTrace

当前 moderation 响应已经具备 `semantic_traces`，但 trace 还没有成为跨导入、审核、投影、治理的统一对象。

建议后续补：

```text
SemanticTrace
  - mention_id
  - normalization_decision_id
  - concept_id
  - assertion_id
  - condition_set_id
  - evidence_ids
  - projection_id
```

### 6.3 NatureFlavor 深化

当前 `甘/苦/辛/酸/咸` 和 `寒/热/温/凉` 已经会生成 `NatureFlavor`，但还没有完整药性理论扩展。

建议后续升级为：

- 升降浮沉
- 有毒/无毒
- 偏性强弱
- 性味与归经/剂量的联合条件

### 6.4 经络/脏腑体系

当前已覆盖十二经脉到脏腑的最小映射、十二经脉 `FLOWS_TO` 顺接关系，补充了奇经八脉的最小词表与 `meridian_system` 分类，并进一步补充了 `MeridianSystem`、`ZangFu` 独立节点，以及 `Meridian -> BELONGS_TO_MERIDIAN_SYSTEM -> MeridianSystem`、`Meridian -> ASSOCIATED_WITH_ZANGFU -> ZangFu` 的可校验关系。腧穴侧已支持 `Acupoint -> LOCATED_ON_MERIDIAN -> Meridian` 的腧穴归经关系、腧穴 `location_text/location_reference/location_direction/location_distance/location_unit` 定位属性、腧穴 `method_text` 手法属性、`Acupoint -> COMBINES_WITH -> Acupoint` 的腧穴配伍关系、`Acupoint -> INDICATED_FOR_SYMPTOM -> Symptom` 的主治关系，以及腧穴语境下 `Meridian -> MANIFESTS_AS_SYMPTOM -> Symptom` 的经络病候表现关系，但仍未形成完整经络体系。

建议后续补：

- 详细经络循行路线
- 经络循行与病候关系的分段、证据化扩展
- 腧穴标准定位结构深化、手法结构化、配伍适用条件

### 6.5 剂量范围推理

当前剂量作为 `Dose` 节点，已能解析最小范围、单位、频次和剂数，并支持 `gt/gte/lt/lte/between` 数值条件匹配；但还没有完整风险推理。

建议后续补：

- usage context
- overdose risk condition
- population-specific dose adjustment
- medication-specific overdose threshold

## 7. 阶段性结论

当前项目已经完成了从“审核知识卡”向“本体基座”的关键转向：

- 真相层逐步转向 assertion/evidence/condition。
- projection 成为 read model。
- 关系 schema 具备校验和发布门禁。
- 条件化断言已进入查询和审核运行时。
- 术语归一已从审核日志前移到导入治理。
- 中医核心结构开始具备图谱骨架。

但当前仍应视为 **中医本体基座 v0.1 的工程化雏形**，不是最终成熟形态。

后续重点应从“补结构”转为“治理流、版本流、深层推理能力”的增强。
